# Task19 报告数据集管理设计

## 1. 结论

Task19 建设“报告数据集管理闭环”，同时补齐后台管理接口和前端管理页面。采用“分页列表 + 独立编辑页”，不把复杂字段策略塞进抽屉，也不要求管理员直接编辑整段 JSON。

本阶段只管理报告数据集，不同时开发项目全景方案、组合报告模板和项目问题规则页面。继续使用当前配置覆盖模式：同一 `datasetCode` 只有一份当前配置，不增加发布记录或历史版本表。

## 2. 当前代码事实

后台仓库位于 `D:/IdeaProjects/mc-ai`，Task19 实际开发继续在后台隔离工作树进行。当前已经具备：

- `ai_report_dataset` 和 `ai_report_dataset_field` 两张当前配置表；
- `ReportDataset`、`ReportDatasetField`、Mapper 和 `ReportDatasetServiceImpl`；
- 保存时的事务、乐观锁、配置校验和及字段策略校验和；
- 已发布工作流解析，以及主图和 `FOREACH` 子图的 READ 能力检查；
- 运行时参数映射、字段安全策略和数据集执行能力；
- `/api/agent/admin/**` 的 `ai_agent_admin` 权限边界。

当前缺少：

- 数据集分页、详情、独立校验和启停管理接口；
- 数据集管理 DTO、VO 和前端 API；
- 数据集列表及结构化编辑页面；
- 保存阶段对 `query`、`access` 参数映射结构和工作流输入 Schema 的完整检查。

前端仓库位于 `D:/TraeProject/enterprise-vue-admin`，技术栈为 Vue 3、Element Plus 和 Vite。现有路由、侧栏、列表页、字段字典和工作流分页接口可以复用。

## 3. 方案选择

### 3.1 采用方案：列表页 + 独立编辑页

- 列表页只负责筛选、查看状态、进入新增/编辑和启停。
- 编辑页分区维护基础配置、工作流、参数映射和字段策略。
- 页面职责清晰，后续增加字段策略时不会继续放大单个列表组件。

### 3.2 未采用方案

- 列表页抽屉编辑：初始文件较少，但字段策略和参数映射会让抽屉过长，组件难维护。
- 原始 JSON 编辑器：代码更少，但管理员容易写错结构，无法满足工作流和字段字典选择体验。

## 4. 后台接口

新增管理端 Controller，根路径为：

```text
/api/agent/admin/report-datasets
```

接口范围：

```text
GET   /pageList          分页查询当前数据集
GET   /detail/{id}       查询数据集及字段策略
POST  /validate          校验配置，不写数据库
POST  /save              新增或覆盖当前配置
POST  /{id}/status       启用或停用当前配置
```

所有接口继续由现有 `AgentAccessInterceptor` 要求 `ai_agent_admin` 权限。Controller 只处理请求和返回转换，操作人统一从 `CurrentUserProvider` 获取。

分页查询参数：

- `current`、`size`；
- `keyword`：匹配数据集编码或名称；
- `domainCode`；
- `enabled`。

分页只返回列表所需字段，包括 ID、编码、名称、业务域、主体类型、查询工作流、字段数量、启停状态、乐观锁版本和更新时间。详情才返回完整参数映射和字段策略。

## 5. 保存模型和状态规则

前端使用结构化 DTO，不直接提交 Entity：

- 基础配置：ID、版本、编码、名称、业务域、主体类型、TTL、关联方式、最大并发数和启停状态；
- 工作流：查询工作流编码、可选的独立权限工作流编码；
- 参数映射：`query` 和 `access` 两组键值映射；
- 字段策略：字段字典 ID、事实编码、事实名称、事实类型、粒度、脱敏策略、展示顺序及五个安全开关。

保存规则：

1. 新增时 `id` 为空；更新时必须同时携带 `id` 和 `version`。
2. `datasetCode` 创建后不可在编辑页修改，避免快照和方案引用漂移。
3. 同一编码仍更新当前行，不创建历史版本。
4. 保存事务继续整体替换当前字段策略；失败时全部回滚。
5. 乐观锁冲突返回 409，前端保留表单并提示刷新后重新确认。
6. 不提供物理删除。已有快照、报告或全景方案可能按稳定编码引用数据集，停用可以达到退出运行的目的且更安全。

## 6. 配置校验

`validate` 和 `save` 必须调用同一套配置校验逻辑，不能复制两套规则。

### 6.1 基础配置

- 编码、名称、业务域、关联方式不能为空并执行长度和格式检查；
- 主体类型只能来自现有 `PROJECT`、`PERSON`、`DEPARTMENT`；
- TTL 保持 1 至 1440 分钟；
- 最大并发数必须大于 0；
- 字段策略至少一项，事实编码在同一数据集内唯一；
- 脱敏方式只接受运行时已经支持的稳定值。

### 6.2 工作流

- 查询工作流必须存在当前可运行的已发布版本；
- 独立权限工作流可以为空；配置后必须存在当前可运行的已发布版本；
- 两类工作流的主图和全部 `FOREACH` 子图都只能调用 READ 能力；
- 管理页工作流选择器复用现有工作流分页接口，默认筛选已发布且启用的工作流；后台仍进行最终校验，不能相信前端筛选结果。

### 6.3 参数映射

数据库继续保存既有结构：

```json
{
  "query": {
    "projectCode": "project_code",
    "startDate": "start_date"
  },
  "access": {
    "projectCode": "project_code"
  }
}
```

- 根节点必须同时包含 `query` 和 `access` 对象；没有独立权限工作流时 `access` 允许为空对象；
- 接口没有时间条件时无需配置 `startDate`、`endDate`，不得自动补时间参数；
- 每个目标参数必须存在于对应工作流 `inputSchema.properties`；
- 同一映射组不能把多个规范参数映射到同一目标参数；
- 保留字段继续由 `ReportDatasetValidator` 拒绝；
- 工作流 Schema 声明的必填目标参数必须存在映射，但校验配置时不要求提供运行时值；实际执行时继续检查非空运行值。

### 6.4 字段策略

- `fieldId` 必须对应实际存在的字段字典；
- 字段必须属于查询工作流能够读取的能力范围；
- 页面从字段字典选择后带出字段名称和类型，管理员配置稳定事实编码和安全策略；
- `calculable`、`displayable`、`exportable`、`modelVisible`、`filterable` 分别保存，不互相推断；
- 校验只使用字段元数据，不调用真实 PM 业务查询，不读取用户业务数据。

校验成功只表示配置结构和引用可用，不代表下游 PM 接口当前一定返回数据。

## 7. 前端页面

### 7.1 路由和菜单

在“AI能力中心”增加“报告数据集管理”：

```text
/knowledge/report-dataset/index
/knowledge/report-dataset/save/:id?
```

沿用 `/knowledge` 的管理员路由守卫；真正权限继续以后端为准。

### 7.2 列表页

筛选项：编码或名称、业务域、启停状态。

主要列：数据集编码、名称、业务域、主体类型、查询工作流、字段数量、状态、最后修改时间和操作。

操作只包含新增、编辑和启停。启停失败时恢复开关原值。列表查询条件写入路由参数，编辑返回后恢复分页和筛选条件。

### 7.3 编辑页

编辑页使用四个清晰区域，不新增页面编排框架：

1. 基础配置；
2. 查询与权限工作流；
3. 参数映射表；
4. 字段与安全策略表。

工作流通过下拉搜索选择，不要求管理员记忆编码。参数映射通过“规范参数 → 工作流参数”的行式表格编辑，由前端组装成后端既有 JSON 结构。

字段策略通过字段字典选择弹窗添加。策略表直接编辑事实编码、名称、粒度、脱敏方式、展示顺序和五个布尔开关。前端只做必填、重复项和数值范围等即时提示，所有安全规则仍由后台重新校验。

页面提供“校验配置”和“保存”两个按钮：

- 校验只返回成功或明确错误，不写数据库；
- 保存再次执行完整校验，不能依赖此前校验结果；
- 失败时保留用户输入，不跳转、不清空表单；
- 保存成功后返回列表并恢复原筛选条件。

## 8. 数据流

```text
管理员打开列表
→ 管理接口按条件分页
→ 进入新增或编辑页
→ 选择已发布工作流和字段字典
→ 页面组装结构化配置
→ 可选执行只读配置校验
→ 保存时后台再次完整校验
→ 事务写入当前数据集和字段策略
→ 返回最新 ID、版本和校验和摘要
→ 后续业务查询按最新启用配置执行
```

后台不执行真实业务工作流作为配置校验手段，避免管理操作越权读取 PM 数据。

## 9. 异常与安全

- 未登录返回现有认证错误；非管理员返回 403；
- 配置格式或字段错误返回 400；
- 工作流未发布、已失效或并发修改返回 409；
- 唯一编码冲突返回 409；
- 返回值不包含工作流运行结果、授权令牌、PM 原始响应或业务快照内容；
- 日志只记录数据集编码、操作类型和安全错误分类，不记录参数实际值或业务数据；
- 前端不根据路由状态伪造管理员身份。

## 13. 完成标准

1. 管理员可以分页查看、创建、编辑、校验、启用和停用报告数据集；
2. 管理员通过工作流和字段字典选择完成配置，不需要逐段手写 JSON；
3. 无时间条件的接口不会被强制增加时间映射；
4. 保存前可以发现工作流、参数映射和字段策略错误；
5. 保存后的当前配置可以被现有业务查询链路直接读取；
6. 不引入新表、新依赖、历史版本和物理删除；
7. 修改保持中文注释、职责清晰、文件规模可维护；
8. 后台相关测试、前端新增测试和生产构建通过，已知基线问题独立列出。
