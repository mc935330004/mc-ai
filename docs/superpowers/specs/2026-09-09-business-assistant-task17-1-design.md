# Task17.1 业务助手契约补全设计

## 1. 目标

本阶段只补齐 Task17 已经要求、但当前提交 `6bbe516` 尚未形成闭环的两项后端能力：

1. 项目追问在同一用户、会话、项目和查询条件下优先复用有效项目全景快照；明确刷新时重新查询。
2. 单人员查询返回安全的章节快照引用，并使用这些引用创建 XLSX、DOCX 或 PDF 组合报告任务。

本阶段不进入前端，不实现部门成员目录和部门报告，也不改变人员固定六类数据集契约。后两项分别作为 Task17.2、Task17.3 处理，避免在没有明确部门成员契约和考勤依赖闭包时伪造实现。

## 2. 方案选择

### 采用方案：聚焦服务补契约

- 新增项目全景快照读取服务，在服务内部完成当前权限复核、归属校验、查询哈希、配置校验和、字段策略校验和、有效期检查及安全事实解析。
- 人员查询只增加不透明 `snapshotId` 和字段策略校验和，不返回工号、认证上下文或原始事实。
- 将项目和人员报告任务组装提取到一个聚焦服务，业务助手入口只负责选择“复用或查询”和发送回答。

选择该方案是因为它复用现有快照、权限、报告任务和 SSE 协议，不新增表、不修改 Flyway、不引入依赖，也不让 `BusinessAssistantServiceImpl` 直接访问 Mapper。

### 不采用方案

- 不在 `BusinessAssistantServiceImpl` 中直接查快照 Mapper：会绕过复权和字段策略边界，并继续扩大该类。
- 不新增通用编排框架或事件总线：当前两个契约补口不需要新的平台抽象。
- 不把部门查询一起塞入本阶段：当前缺少“已选部门到授权人员集合”的稳定输入契约，且部门导出需要单独的聚合快照设计。

## 3. 项目快照复用

业务助手只读取服务端会话状态继承的 `panoramaSnapshotId`，不接受客户端 `extra` 中的同名值。非刷新请求先调用项目全景快照读取服务：

1. 使用当前登录凭证和项目选择令牌重新定位、授权项目。
2. 校验聚合快照属于当前用户、会话和稳定项目 ID。
3. 校验规范查询哈希、项目类型、当前全景方案 ID 与配置校验和。
4. 按当前方案顺序读取模块引用；每个可复用模块必须重新执行数据集权限校验。
5. 校验业务快照未过期，数据集配置及字段策略校验和仍为当前值。
6. 仅解析快照中的 `display`、`model` 安全通道，并恢复已保存的问题结论。
7. 任一校验不通过时返回空结果，由现有项目全景执行服务安全重查；明确刷新直接跳过复用。

复用成功后不得调用项目模块查询。回答和报告仍引用原有模块快照，保证同一轮对话和导出数据一致。

## 4. 人员报告快照引用

`PersonBusinessQueryService` 在模块执行成功或无数据并创建快照后，返回：数据集编码、模块状态、完整性、不透明快照 ID、字段策略校验和。复用快照时返回同样的安全引用。

- `SUCCESS`、`EMPTY`、`REUSED` 可以携带快照引用。
- `DENIED`、`FAILED`、`TIMEOUT` 不得伪造快照引用。
- 返回对象不得包含真实工号、Authorization、secureContext、原始响应或字段策略处理前事实。

业务报告组装服务根据人员模块终态构造当前模板章节，再调用现有 `BusinessReportPlanService.plan(...)` 和 `CompositeReportTaskService.create(...)`。部分失败继续创建不完整报告；无权限章节保持安全状态，不泄露数据存在性。

## 5. 边界与错误处理

- 项目快照权限撤销：主体定位或模块复权失败，禁止读取旧快照；按现有失败关闭语义返回。
- 项目快照过期、查询变化、配置变化或字段策略变化：不复用，重新查询。
- 人员报告任务创建失败：保留已完成的确定性查询回答，并增加安全失败说明。
- 模型总结失败：不影响快照引用、确定性事实和已创建的报告任务。
- 本阶段不新增 SQL；简单读取继续使用 MyBatis Plus Wrapper。若后续确需复杂 SQL，必须写入对应 `Mapper.xml`。

## 6. 验收标准

1. 项目非刷新追问复用有效全景快照，项目模块调用次数为零。
2. 明确刷新绕过复用并执行现有项目全景查询。
3. 伪造、过期、越权、查询不匹配、方案变化或字段策略变化的项目快照不能复用。
4. 复用回答恢复模块状态、安全展示事实、模型可见事实、问题结论和完整性。
5. 人员查询的新建与复用路径都返回安全章节快照引用。
6. 人员 PDF/XLSX/DOCX 请求创建真实报告任务并返回 ArtifactBlock，不再输出“暂未创建”占位。
7. 候选页仍不执行模块查询；RAG、写操作和普通工作流路径不变。
8. 新增/修改测试先失败再实现，聚焦测试和 `mvn -pl ai-agent -am clean test` 均通过后才允许提交。
