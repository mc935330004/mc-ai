# 生产安全与质量稳定性收口记录

## 1. 范围与结论

本轮对应全项目推荐完善顺序中的前两个阶段：

1. 第一阶段：生产安全收口。
2. 第二阶段：质量与稳定性。

代码实现与静态检查已经完成，但运行、压测、故障演练和真实账号验收尚未执行，因此不能把“代码完成”写成“生产验收通过”。

明文密钥和历史密钥轮换按用户要求排除，由用户后续单独处理。

## 2. 第一阶段：生产安全收口

已完成：

- `/api/agent/**`、`/api/knowledge/**` 和旧 `/api/aiAgent/**` 统一进入访问拦截器。
- 普通用户接口与管理接口分离，管理接口要求 `ai_agent_admin`。
- 知识文档、版本、切片、问答、日志和引用按租户与部门隔离。
- 能力与工作流支持 `PUBLIC / RESTRICTED` 人员访问范围，并在候选、执行、WRITE确认和重试链路复验。
- 旧直连聊天入口默认关闭。
- 知识分类删除接口使用 `DELETE`。
- Cookie写请求校验浏览器Origin。
- 生产环境强制启用SSO、Secure Cookie和HTTPS地址，错误配置阻止启动。
- Ticket交换与其他认证接口按客户端地址限流，Redis键不保存原始地址。
- 全局上传硬上限由500MB收紧至100MB，具体能力字段仍可配置更小限制。
- 前端依赖锁文件已更新到无已知 `npm audit` 漏洞的兼容版本。

待运行环境验收：

- 使用真实授权、未授权和撤权账号验证能力与工作流。
- 使用两个租户、两个部门验证文档、切片、日志、引用和RAG命中隔离。
- 验证反向代理传递HTTPS协议，浏览器Cookie实际携带 `Secure`。
- 验证旧聊天入口未注册，GET删除接口返回方法不支持。

不在本轮范围：

- 明文密钥移除与历史密钥轮换。
- HTTPS证书申请、域名解析和网关部署。

## 3. 第二阶段：质量与稳定性

已完成：

- 知识库SSE由公共线程池改为专用有界线程池。
- SSE设置有限超时，并在超时、异常和客户端断开时取消后台任务。
- 线程池过载时快速返回503，不继续堆积任务。
- 普通接口与聊天、知识问答、上传、调试、模型测试等高成本接口分级限流。
- 限流计数存储在Redis，多实例部署保持一致。
- Redis限流使用原子脚本同时写入计数和过期时间，不产生永久限流键。
- PM身份服务和业务能力HTTP调用增加连续故障熔断。
- SSO Ticket交换、PM权限解析与WRITE权限复验统一增加有限超时或熔断保护。
- 明确业务4xx不计入外部服务故障，避免误熔断。
- Actuator暴露MySQL、Redis和外部服务熔断健康状态。
- 生产环境启用优雅停机，并配置Redis、业务接口和SSE有限超时。
- 增加结果快照、运行轨迹、模型调用、知识问答、已删除会话、终态待确认操作、已解决告警和审计日志的分批清理任务。
- 数据清理默认关闭，只有确认备份与保留期限后才通过生产环境变量显式开启。
- 审计数据保留时间默认长于普通运行数据。
- V11补充数据清理条件索引，避免定时任务对运行大表执行无索引扫描。
- 后端增加生产配置、限流策略、熔断和保留策略测试。
- 前端增加SSE分片、完成事件和多行数据解析测试。
- 前端增加聊天页收到基础报告后立即渲染的Playwright端到端回归测试。
- 流式接口收到HTTP 200业务异常JSON时直接报错，不再被误判为空SSE。
- 后端与前端仓库分别增加CI质量门禁。

当前数据保留默认值：

| 数据类型 | 默认保留期 |
|---|---:|
| 结果快照 | 使用快照自身 `expires_at` |
| 普通运行记录 | 90天 |
| 模型调用记录 | 180天 |
| 知识问答与引用 | 180天 |
| WRITE及模型配置审计 | 365天 |

待运行环境验收：

- 执行后端测试、前端测试和构建。
- 验证CI在实际Git仓库分支上触发。
- 对聊天和知识库SSE进行并发与断连压测。
- 模拟PM、业务系统、Redis、MySQL和模型服务不可用。
- 检查限流、熔断恢复、健康端点和清理任务指标。
- 在数据备份环境验证清理SQL执行计划、锁等待和批次耗时。

## 4. 发布前配置

生产环境至少需要补齐以下非敏感地址和策略变量：

```text
PM_BASE_URL=https://...
PM_LOGIN_URL=https://...
PM_AI_ASSISTANT_URL=https://...
BUSINESS_API_BASE_URL=https://...
AGENT_ALLOWED_BROWSER_ORIGINS=https://...
REDIS_HOST=...
DATA_RETENTION_ENABLED=false
```

敏感变量及密钥由用户自行处理，本文件不记录真实值。

首次启用数据清理前必须备份数据库、人工执行V11新增清理索引，并在备份环境检查SQL执行计划。
