# PM Agent - AI Report 重构与访问控制闭环记录

## 1. 文档说明

原需求文档已在提交 `c9a3a6e` 中删除。本文件以精简方式恢复当前有效的实施状态，不恢复已经失效的逐轮代码示例，避免历史方案继续误导开发。

## 2. 已闭环能力

### 2.1 AI Report 主链

- 后端业务结果统一转换为 `ReportSchema`，前端固定组件负责渲染。
- `DATA_QUERY` 直接展示业务报告，`ANALYSIS_REPORT` 在基础报告后追加 AI 分析。
- 专用 Java `ReportTemplate` 优先，后台 `ReportDefinition` 作为普通模块的通用配置能力。
- 报告支持固定区块、普通列表、树形数据、文件字段和分析状态。
- 报告后的二次问答复用上一次安全结果快照，不依赖前端回传完整业务数据。
- 工作流与报告快速配置支持真实样例、字段识别、报告预览和回写编辑器内存草稿。

### 2.2 模型配置

- 支持系统模型配置、人员模型授权、聊天选模和失败切换。
- 支持模型连通性测试、配置缓存失效、乐观锁和配置审计。
- 旧版 `/api/aiAgent/**` 模型直连接口默认关闭，只允许通过环境变量临时回滚开启。

### 2.3 能力与工作流人员访问控制

- 能力和工作流统一支持 `PUBLIC` 与 `RESTRICTED` 两种运行范围。
- `PUBLIC` 对所有已登录人员开放；`RESTRICTED` 仅允许名单中的 PM 用户编码运行。
- 候选召回阶段先过滤无权资源，防止无权资源进入模型选择上下文。
- 能力、工作流、失败重试、WRITE 二次确认、动态选项和文件上传在真正执行前再次校验权限。
- 权限配置绑定资源定义，不绑定发布版本；发布新版本后继续沿用当前访问策略。
- 管理端编辑、发布和能力测试由管理员权限保护，不要求管理员加入业务运行名单。
- 保存权限时锁定资源定义并在同一事务内替换授权名单，避免并发覆盖产生半完成状态。

### 2.4 知识库租户与部门隔离

- 知识文档写入服务端认证得到的 `tenantId`，不接受前端伪造租户和部门标识。
- 支持租户内公开 `PUBLIC` 和本部门可见 `DEPARTMENT`。
- RAG 只检索当前租户、当前人员可见、已经发布且有当前版本的文档。
- 文档列表、概览、状态变更、版本发布、重新向量化、切片列表和切片启停均校验租户。
- 问答日志、统计、详情和引用记录均按当前租户隔离，并记录实际提问人。
- Agent 异步聊天在请求线程捕获可信知识库身份，避免异步线程读取已经失效的 `HttpServletRequest`。
- 仅携带旧 `Authorization` 的普通业务聊天保持兼容；真正进入知识库查询时必须存在有效 Agent 会话。

### 2.5 接口安全与契约整理

- Agent、知识库和旧版 AI 接口统一进入登录与管理员边界。
- 普通用户仅访问聊天、待确认操作、动态表单和知识库问答接口，其余管理接口要求 `ai_agent_admin`。
- Cookie 写请求校验浏览器 `Origin`，降低跨站请求风险。
- 知识分类删除改为 `DELETE`，不再用 `GET` 执行状态变更。
- 已清理前端中没有后端实现且没有页面调用的知识分类详情旧接口、向量任务详情和重试旧接口。

## 3. 数据库变更

本轮数据库内容统一追加在：

`ai-agent/src/main/resources/db/migration/V11__create_action_audit_log.sql`

包含：

- 能力和工作流 `access_scope` 字段。
- `ai_agent_resource_user_grant` 人员授权表。
- 知识文档 `tenant_id`、`access_scope`、`owner_dept_id` 字段及索引。
- 知识问答日志 `tenant_id`、`user_id` 字段及索引。

当前 Flyway 已关闭，发布前必须手工执行对应 SQL。历史知识文档的 `tenant_id` 无法可靠自动推断，必须按真实租户归属补齐；未补齐的数据不会参与新隔离规则下的列表和检索。历史问答日志保持空租户，不自动填充虚假归属。

## 4. 当前限制与风险

- 人员权限当前以 PM 登录账号区分大小写保存；项目未发现可复用的 PM 人员搜索接口，因此配置页只校验格式和数量，不能在保存前验证账号是否真实存在。
- 能力和工作流授权当前是全局资源策略，不按租户分别配置。如果未来同一资源需要不同租户维护不同名单，需要为授权表和管理接口增加租户维度。
- 当 `agent.sso.enabled=false` 时，统一身份和管理员拦截按现有兼容策略不生效；生产环境必须保持 SSO 开启。
- 本轮按约定只做静态检查，没有运行 Maven 编译、测试、Flyway、前端构建、接口请求或浏览器验收，不能把这些运行结果表述为已经通过。

## 5. 发布前人工核对

1. 手工执行 V11 中本轮新增的访问控制和知识库隔离 SQL。
2. 按真实租户归属补齐历史 `knowledge_document.tenant_id`，不要对多租户数据做统一错误回填。
3. 确认生产环境 `agent.sso.enabled=true`，并正确配置允许的浏览器 Origin。
4. 用未配置名单的普通人员验证受限能力和工作流不会被召回，也不能通过直接执行、重试或确认操作绕过。
5. 用已授权人员验证能力、工作流、动态选项和文件上传可以正常执行。
6. 分别使用两个租户和两个部门验证知识文档、切片、问答日志和 RAG 命中结果互不可见。
7. 验证普通业务聊天、知识库问答、报告生成和历史恢复没有受到访问控制改造影响。
